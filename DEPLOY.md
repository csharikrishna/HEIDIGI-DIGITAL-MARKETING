# Hei Digi deployment runbook

**Legal notice:** Have a qualified Indian lawyer review the Privacy Policy, Terms, Cookie Policy and Disclaimer before launch. The policy text is a practical draft, not legal advice.

## 1. What Vercel should serve

- Production domain configured in `site.config.json`: `https://heidigi.com`.
- Build command, generated by `build.py`: `python3 -m pip install -r requirements.txt && python3 build.py`.
- Output directory: `dist` only. Do not configure the project root as the static output directory.
- Install/build dependency: `Pillow==12.3.0`, pinned in `requirements.txt`.
- `build.py` remains the source of truth for generated HTML, `sitemap.xml`, `robots.txt`, `vercel.json`, CSP, metadata and JSON-LD. Do not manually edit generated root HTML or `dist` HTML.

## 3. Domain, DNS and redirects

1. Confirm ownership/registration of `heidigi.com`; this repository does not purchase the domain or change DNS.
2. Add the apex and `www` domain in Vercel and wait for the HTTPS certificate to issue.
3. The generated `vercel.json` redirects `www.heidigi.com` to `https://heidigi.com` with a permanent redirect. After deployment verify both HTTP and HTTPS and both hostnames.
4. Test after deployment:

```bash
curl -sI https://heidigi.com/ | grep -iE '^HTTP|content-security|x-content-type|referrer|permissions|cross-origin|strict-transport'
curl -sI https://www.heidigi.com/ | grep -iE '^HTTP|location'
curl -sI http://heidigi.com/ | grep -iE '^HTTP|location'
curl -s -o /dev/null -w '%{http_code}\n' https://heidigi.com/not-a-real-page/  # expect 404
curl -sI https://heidigi.com/services/meta-ads/ | head
curl -s https://heidigi.com/robots.txt
curl -s https://heidigi.com/sitemap.xml | head
curl -sI https://heidigi.com/build.py  # expect 404, not source code
curl -sI https://heidigi.com/site.config.json  # expect 404
curl -sI https://heidigi.com/content/services.json  # expect 404
curl -sI https://heidigi.com/docs/reports/SEO-AND-IMPLEMENTATION-REPORT.md  # expect 404
curl -sI https://heidigi.com/api/services.json  # expect 404; the app does not need a public API services file
```

The expected 404s must be confirmed against the real Vercel deployment; local static output tests cannot prove live edge behavior.

## 4. Security headers and HSTS

`vercel.json` is generated by `build.py` and includes the existing strict CSP, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, and `Cross-Origin-Resource-Policy: same-site`. Static CSS/JS use immutable caching because their URLs include content hashes; fonts/OG/work/client media use shorter caching.

The configured HSTS is currently `max-age=300` seconds, the first ramp step. Only after confirming valid HTTPS on apex and `www`, and no mixed content, increase `hstsMaxAge` to `86400`; verify for a suitable period, then increase to `31536000`. Do not add `includeSubDomains` or `preload` until every subdomain is HTTPS-only and the domain owner intentionally accepts the long-lived policy.

`/.well-known/security.txt` is generated. Review its contact address before going live.

## 5. Enquiry endpoint setup

The site currently has `leadEndpoint` empty, so the form opens WhatsApp and provides email/phone fallbacks. The Vercel function is present and unit-tested with mocked provider responses, but it does not deliver real emails until configured.

In Vercel Production Environment Variables, set:

- `RESEND_API_KEY`: Resend API key (secret, never commit it).
- `LEAD_TO_EMAIL`: inbox that should receive enquiries.
- `LEAD_FROM_EMAIL`: verified sender on a domain controlled by you.
- `SITE_ORIGIN`: exactly `https://heidigi.com`.
- Optional `TURNSTILE_SECRET`: Cloudflare Turnstile secret; add the public site key to `site.config.json` as `turnstileSiteKey`.
- Optional `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`: HTTPS REST URL/token for distributed per-IP rate limiting. If not set or temporarily unavailable, the function falls back to the per-instance in-memory limiter, which is best-effort.

Then set `leadEndpoint` to `/api/lead`, rebuild and redeploy. Verify a real enquiry arrives and provider credentials work. A `POST` without valid origin or setup should never appear to succeed. The form must show a clear failure and working WhatsApp/call/email alternatives.

**Rate limiting:** default 5 requests per IP per 10-minute window. Use Upstash for a shared counter across serverless instances; also consider Vercel Firewall/WAF rules for edge protection. The in-memory fallback alone is not a global limit.

## 6. Analytics and consent

GA4 and Plausible are off until an ID/domain is configured in `site.config.json`. The code shows a consent banner and loads analytics only after the visitor accepts. Do not enable advertising pixels until their consent, disclosure and CSP requirements have been reviewed. After enabling analytics, test that Decline keeps analytics scripts from loading, Accept loads only the configured provider, and Privacy settings reopens the choice.

## 7. Search indexing

1. Verify `https://heidigi.com` in Google Search Console and Bing Webmaster Tools.
2. Submit `https://heidigi.com/sitemap.xml`.
3. Inspect the homepage, `/services/seo/`, one industry page and one location page. Check canonical selection, rendered content, indexing eligibility and mobile usability.
4. Confirm Hei Digi's Google Business Profile NAP exactly matches the configured address/phone. No ranking or traffic outcome is guaranteed.
5. Real search-volume numbers require Keyword Planner or another keyword-data provider; this build does not invent search-volume figures.

## 9. Final QA and rollback

- Build: `python3 build.py`.
- Static source/output audit: `python3 tools/audit.py`.
- Alternate domain/security config: `python3 tools/test_build_modes.py`.
- Form/API tests: `node tools/test_lead.js && node tools/test_api.js`.
- JavaScript syntax: `for f in assets/js/*.js api/*.js; do node --check "$f" || exit 1; done`.
- Internal links: `python3 tools/crawl_links.py`.
- Browser tests: `python3 tools/browser_test.py` and `python3 tools/browser_features.py` require Playwright plus Chromium. These could not run in this packaging environment; CI installs Chromium.
- Lighthouse: `npx @lhci/cli autorun --config=lighthouserc.mobile.json` and the desktop config. Lighthouse is not installed/run in this environment, so no score is claimed.

For rollback, promote the previous good Vercel deployment. If a security header blocks a required resource, fix it in `build.py` and redeploy; do not disable the CSP as a shortcut.
